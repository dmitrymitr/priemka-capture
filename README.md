# Приёмка — ревизия 2 (1.1.2)

Веб-приложение: https://dmitrymitr.github.io/priemka-capture/

APK выпускается через GitHub Actions после проверки подписи и состава файлов. См. Releases.

- PDF на обход: загрузка в начале или в процессе, локальное хранение, быстрый просмотр и возврат.
- Личные настройки и отдельные флаги обхода: типовые нарушения ПБ, съёмка подряд. По умолчанию выключены.
- 65 пар ПБ из сохранённого `catalog.json` исходного файла «Список дефектов - приемочная ведомость [eugZCt].xlsx». `docs/pb-catalog.js` хранит исходные сокращённые и полные формулировки; подстановка только по нажатию.
- Черновик новой записи: IndexedDB + синхронная аварийная копия текста, восстановление последнего экрана; завершённые черновики не возвращаются.
- Смена раздела сохраняет текущую запись в прежнем разделе. История других записей не переписывается.
- Съёмка подряд через getUserMedia с возвратом к обычной камере при отказе. Снимки сохраняются без подтверждения кадра.
- Фото отдельной записи или всего обхода — через системное меню в фототеку, пакетами по 20. Действие сохранения на iOS выполняет пользователь.
- Два формата ZIP: по умолчанию быстрые исходники JSON/CSV и media с неизменёнными фото/аудио; по выбору готовый XLSX с фотографиями. Части по разделам: до 25 замечаний или около 50 МБ, крупное одиночное замечание отдельно. Прогресс, отмена и только одна подготовленная часть в памяти. PDF сохраняются отдельно. Имена: `Объект_23.10.2026_ПБ_ч.1 из 3.zip`. Косая черта заменена словами «из», поскольку `/` недопустим в имени файла.
- Пошаговая передача: скачать → найти файл → поделиться. Генерация отдельно от передачи сохраняет пользовательское нажатие для Web Share.
- Выборочное удаление обхода и вложений с подтверждением, сохранение настроек и остальных данных.
- Последние записи сверху.

## Проверка кандидата

`tests/revision2.cjs` — браузерный сценарий новых функций; `tests/upgrade.cjs` — загрузка исходной версии из Git HEAD и обновление без изменения данных. Для запуска нужен Playwright и локальный HTTP-сервер на 8765. `PLAYWRIGHT_MODULE` может задавать путь к пакету. Старые `tours.cjs`/`revision1.cjs` описывают прежний JSON/CSV-экспорт и прежнюю навигацию, поэтому не являются актуальным критерием нового интерфейса.

Проверено в Chromium: PDF сохраняется и доступен из обхода; аварийный черновик с фото восстанавливается даже при незавершённой асинхронной записи; выбор раздела не меняет прежние записи; каталог и настройки; два кадра подряд; удаление фото; подготовка передачи фото; XLSX-only ZIP; выборочное удаление; обновление 1.0.2 → 1.1.2 с сохранением записей, черновика и старого аудио. XLSX прочитан openpyxl, проверены фото, XML и CRC.

До выпуска проверить на реальных iPhone/iPad: сворачивание Safari и блокировка, PDF-просмотр, камера, «Сохранить изображения», открытие XLSX в Excel. Настольный браузер не подтверждает работу всех системных меню iOS. Редактирование уже сохранённой записи по-прежнему требует нажатия «Сохранить». Не обещать исправление физического сценария iPad только по тесту Chromium.

Excel содержит введённый текст; не выполняет ИИ-обработку, проверку норм или расшифровку старых аудио. Фото для ведомости преобразуются в JPEG до 1600 px, оригиналы остаются на устройстве. Исходные JSON, аудио и PDF не включены в документный ZIP. Удалять обход следует только после сохранения нужных материалов.

Android: версия 1.1.2 / versionCode 8. GitHub Actions выполняет assembleRelease, lintRelease и testReleaseUnitTest. Перед выпуском проверяются SHA-256, файлы внутри APK, appId и совпадение сертификата с 1.0.2.

# Приёмка — фото и замечания

## Ревизия 1 · 1.0.2

Фото → описание текстом (можно диктовать микрофоном клавиатуры) → готово. Отдельная аудиозапись удалена. Прежние аудиовложения сохранены и доступны для прослушивания и экспорта.

«Мои обходы» содержит активные и завершённые обходы. В обоих можно редактировать и удалять замечания, добавлять новые. Редактор позволяет менять текст и помещение, добавлять и убирать фото. Изменения применяются одной транзакцией после «Сохранить», отмена сохраняет исходную карточку. Удаление требует подтверждения.

- «Готово → ещё замечание здесь» сохраняет запись в текущем помещении.
- «Следующее помещение» сохраняет запись и начинает другое помещение.
- «Сохранить и к обзору обхода» сохраняет запись и открывает список помещений.
- «К обходу» сохраняет незавершённый черновик.
- «Завершить обход» сохраняет запись, возвращает на главный экран и предлагает ZIP.

После исправлений выгрузите все части ZIP заново. Уже переданные архивы не изменяются.

## Android

APK публикуется в Releases. Обновление 1.0.2 устанавливается поверх 0.2.0 с тем же applicationId и ключом подписи. Не удаляйте прежнюю версию: её локальные записи сохраняются при обновлении. Перед обновлением выгрузите резервный ZIP. Разрешение записи звука приложению больше не требуется; диктовку обеспечивает системная клавиатура.

APK содержит приложение и запускается без интернета. «Передать обход · ZIP» открывает системное меню, где можно выбрать Яндекс Диск. Проверяйте загрузку в самом Диске. APK и браузер используют отдельные хранилища.

## Данные и экспорт

IndexedDB `priemka-capture-v1`, схема 2; существующее хранилище сохраняется. Старые записи без tourId автоматически мигрируют с прежними ID, текстами и вложениями. Материалы не отправляются на сервер приложения.

Имя ZIP: объект, дата начала обхода по местному времени устройства, раздел, короткий код обхода и номер части. Недопустимые символы заменяются, длина названия ограничена для совместимости с файловыми системами.

ZIP: JSON, CSV и исходные вложения; разделение по 25 замечаний или примерно 150 МБ. Пустой обход можно экспортировать. В формате `priemka-capture/2` добавлены `appVersion`, `notes[].updated`, `tour.updated` и `deletedNotes` (список `{id, deletedAt}`, также внутри tour).

Для формирования ведомости предпочтительны все части последней выгрузки обхода. Если объединяются разные выгрузки, обновляйте записи по ID и updated; применяйте удаления из deletedNotes. Новые записи могут появиться после tour.completed: это историческое время завершения, а последующие изменения отмечены updated. Не трактуйте completed как подтверждение или устранение дефектов.

## Запуск и проверки

Статические файлы находятся в docs. Локально: `python -m http.server 8765 --bind 127.0.0.1 --directory docs`.

Тесты Playwright: `node tests/tours.cjs` и `node tests/revision1.cjs`. При необходимости задайте PLAYWRIGHT_MODULE. Проверяются переходы, миграция, офлайн-запуск, восстановление черновиков, редактирование, отмена, сбой записи, фотографии, удаления и экспорт. Реальная камера и диктовка клавиатуры проверяются на устройстве.

Android: `npm ci`, `npx cap sync android`, Gradle `assembleRelease lintRelease testReleaseUnitTest`. CI использует GitHub Secrets для существующего ключа подписи. Увеличивайте versionCode при обновлении APK и CACHE в docs/sw.js при изменении веб-файлов.
